What belongs in this board?

Model APIs, local models, hardware configurations and assisted workflows can all appear. Each result retains its own task, acceptance rule and source. Cross-task ranks are browsing aids, not universal capability scores. Repeated requests are not independent replications; different contributor names are not proof of independence. Availability, uptime, energy and autonomy require their own observations and are not inferred here.

Current seed records come from Second Run campaigns and source-linked TierBench history. Historical summaries are not upgraded into new hardware measurements. Prices are dated observations, not live quotes.

The original site is optional
Operate the same board on your floor.
The kit contains the verifier, source, retained packets and review tools. A new hub has its own name, queue and admission history. It does not phone home.


1. Initialize and inspect
node community/cli.cjs init ./my-hub --name "Our compute desk"
node community/cli.cjs serve ./my-hub --port 8770
Open the printed loopback address. Price and provider links are references, not runtime dependencies. The node helper serves static files and has no write API.
2. Admit evidence deliberately
node community/cli.cjs stage candidate.json --hub ./my-hub
node community/cli.cjs review PACKET_SHA --hub ./my-hub \
  --decision accept --reviewer "Maintainer" \
  --reason "Checked scope and disclosures"
Staging quarantines the exact packet. Review records are append-only. Acceptance confirms your review, not the authenticity of unobserved execution.
3. Build, share and continue
node community/cli.cjs build ./my-hub
node community/cli.cjs verify-feed ./my-hub/site/feed.json
node community/cli.cjs ingest other-feed.json --hub ./my-hub
Imports go into review instead of acquiring another maintainer's approval. Repeated source evidence stays linked; it never becomes another independent replication. Serve the generated site anywhere, or use its standalone result pages offline.

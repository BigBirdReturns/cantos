Decide which deployment to operate

Give the job two existing endpoints, your own application cases, acceptance requirements, scoped operational evidence and sourced cost assumptions. It joins the useful-work verdict, operational gates and cost or energy ranges into one retained deployment decision. Missing required evidence leaves the answer unresolved.

python -B compute/maintainer/job.py validate --manifest deployment-job.json
python -B compute/maintainer/job.py run --manifest deployment-job.json --out deployment-run
python -B compute/maintainer/job.py export --job deployment-run --out deployment-bundle

The kit includes the workbench. Its Decide what to run view prepares job files and imports the returned bundle. Import re-evaluates data using installed code without making model calls. Revised prices or requirements create linked editions; new serving conditions need new observations. Read the job contract for local collection, source-bound resource templates, explicit external grading and the exact supported scope.

Controlled local recovery and storage checks are scoped observations. Cost scenarios are assumptions. They do not establish commercial-cloud ratings, measured full-system costs, or general model rankings.

Start with the real serving comparison

Download the workbench ZIP · Workbench SHA-256 receipt

Extract the workbench ZIP, open a terminal in the extracted cantos folder and run this command with Python 3.10 or later. On Windows you can also double-click open-compute-ledger/start-workbench.cmd.

python -B open-compute-ledger/run.py --open

Choose Review a serving change → Open the real vLLM experiment. This frozen review replays no model inference. Its native verdict is incomparable: baseline and candidate each accepted 21 of 96 requests, below the 77 needed for the recorded 80% requirement. That is a valid negative finding about these tested configurations; it does not mean the measuring instrument failed. The view keeps the policy, changed factors, source identities, evidence hashes, failure-inclusive counts and timing limits beside the verdict.

To open another retained comparison, export it from the maintainer kit and import its ZIP under Review a serving change:

python -B compute/maintainer/maintainer.py export-comparison --analysis YOUR_ANALYSIS --out comparison.zip

A changed policy creates a linked, clearly labeled post-hoc analysis over the same observations, with zero new inference. Changed acceptance rules can change which tasks qualify, but cannot change captured responses or their grades. Download Analysis JSON for that revised policy; Original evidence ZIP remains the source record. The separate Catalog comparison tab supports scoped workload and published price screening, not a universal model ranking. Your retained history stays on your computer.

The example, in one minute

A correction changes the recommendation.

A client requires at least 90% of tasks to be correct and on time. Two configurations process the same 24 fictional invoices. Configuration A costs half as much, but the original grader rejects its explanatory text around otherwise correct JSON.

ORIGINAL GRADING

A: 18 / 24. B: 22 / 24.

Only B clears the acceptance floor.

Recommend B within this sample.

See the original client report

EXTRACT ONE UNAMBIGUOUS JSON ANSWER

A: 22 / 24. B: 22 / 24.

Both qualify; A has half the supplied cost.

A becomes the lower-cost eligible option.

See the revised client report

The desk flags the old calculation and note, records a new calculation, and requires another review before freezing the revised report. The original delivery remains intact. A correct answer that arrived late still fails.

Try it in five minutes.

  1. Open the example. In Client delivery, enter a reviewer name and rationale, record the review and freeze the baseline report.
  2. Return to Start here. Choose Change the contract to extraction. The app opens the comparison and marks the earlier calculation and client note stale.
  3. Choose Record recomputation, then Draft a successor client note.
  4. In Client delivery, review and freeze the revised note. Download its HTML report. Both versions remain available.
  5. Choose Save packet to keep your work. On another visit, use Open packet to restore it.

Use it for one real decision.

1. Bring the evidence.

Start a blank workspace. Add permissioned sources, claims and task-run results in the documented input format. Set quality, deadline and cost rules before comparing runs.

2. Inspect the conclusion.

Keep failed attempts in the bill, compare compatible runs, and review what the evidence supports. Revise a source or rule to see which dependent records need attention.

3. Deliver and retain it.

Export a reviewed client report and save the workspace. A later correction creates a new version rather than silently replacing what the client originally received.

A separate Technical diligence view applies the same approach to supplied contracts, pilots, MOUs, cash receipts and operating-dependency evidence. Inspect its fictional company report.

What the desk does, and what you still do.

The desk organizes supplied evidence, checks its own contracts, computes comparisons, traces recorded dependencies and exports reports. You choose and obtain the evidence, judge source reliability, review conclusions and decide what to tell the client.

It does not run models, fetch live news or quotes, audit a company's systems, publish to BEP, or send corrections to clients. Existing exports may need an adapter. The documentation defines the accepted task-run and diligence formats; native compatibility with BEP's runner has not been established.

Save before closing. This is a single-operator workspace held in browser memory, not a shared cloud account. The demo makes no application upload or model call. For confidential work, use the saved offline copy in an approved environment and export an encrypted backup from the app. Workspace packets contain the text and task outputs you enter.
